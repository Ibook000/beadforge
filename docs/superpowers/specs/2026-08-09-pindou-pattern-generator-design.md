# 拼豆图纸生成器 — 设计文档

日期：2026-08-09
状态：已批准，待实现

## 1. 目标

一个纯前端网页应用。用户上传一张图，调节颗粒度和色卡，得到一张可以照着拼的拼豆图纸，并知道每种颜色要买多少颗豆子。

图片全程在浏览器内处理，不上传任何服务器。

## 2. 非目标

明确不做的事，写下来是为了防止实现时范围蔓延：

- 不做后端、不做账号、不做云端存图。
- 不做完整像素编辑器（画笔、油漆桶、图层、选区）。编辑能力只有三件套，见 §7。
- 不做工程文件（`.json`）的导出/导入按钮。会话恢复走 localStorage，见 §7。
- 不做跨品牌色号互查表。各家拼豆品牌没有官方统一编号标准，唯一可查的开源互查表（`liangdabiao/perlerBeadsApplet`）仓库内无 LICENSE 文件，不引入。
- 不做移动端专门优化。响应式布局保证窄屏能用即可，不为触屏做手势编辑。

## 3. 技术栈

| 项 | 选择 | 理由 |
|---|---|---|
| 构建 | Vite + 原生 TypeScript | 291 色数据表 + 多品牌切换，没有类型很容易写错 |
| 框架 | 无 | 核心是 Canvas 像素操作，虚拟 DOM 只会碍事 |
| 产物 | `vite-plugin-singlefile` 打成单个自包含 HTML | 双击可用，可直接发给别人打开 |
| PDF | jsPDF，打进 bundle | 不走 CDN，保证离线可用 |
| 测试 | Vitest | 只覆盖算法层，UI 不写单测 |

## 4. 架构：一条纯函数管线 + 一个唯一真相

```
原图 File
 └→ 解码 ImageBitmap
   └→ 采样   降到 W×H 格（区域平均，非最近邻）
     └→ 调整   亮度/对比度/饱和度/伽马
       └→ 抠图   透明通道 + 可选纯色背景容差
         └→ 量化   色数上限（Lab 空间 median-cut）
           └→ 匹配   每格 → 调色板最近色（CIEDE2000）[± 抖动]
             └→ 清理   去孤点
               └→ ★ BeadGrid ★
                    ├→ 渲染器（屏幕预览 / 四种图纸样式）
                    ├→ 统计器（用量表 / 采购清单）
                    └→ 导出器（PNG / PDF / 圆豆预览图）
```

`BeadGrid` 是唯一真相。手动编辑直接改它，统计与全部导出都从它派生，因此"手改的那一格"和"导出的图纸"、"统计数字"不可能不一致，无需任何同步逻辑。

管线每一步都是纯函数：输入数据 + 参数，输出新数据，不碰 DOM、不碰全局状态。这样每一步都能独立单测。

### 4.1 数据结构

```ts
/** 一颗豆子在某品牌色卡中的定义 */
interface Bead {
  code: string;      // 品牌色号，如 "F4" / "S01" / "80-15179"
  name: string;      // 原始颜色名；MARD 无颜色名时等于 code
  nameZh: string;    // 中文名（我们补的）
  hex: string;       // "#FC283C"
  rgb: [number, number, number];
  lab: [number, number, number];  // 数据源已预算，直接用
  symbol: string;    // 符号模式用，我们重新生成，见 §6.2
}

interface Palette {
  id: string;          // "mard" | "artkal-s" | "artkal-c" | "perler" | "hama"
  label: string;       // "MARD（漫漫/COCO 系）"
  beadSizeMm: 5 | 2.6;
  beads: Bead[];
}

/** 唯一真相 */
interface BeadGrid {
  width: number;
  height: number;
  paletteId: string;
  /** 长度 width*height，值为 palette.beads 的下标 */
  cells: Uint16Array;
  /** 长度 width*height，1 = 放豆，0 = 空格（透明/背景） */
  mask: Uint8Array;
}
```

`cells` 用 `Uint16Array` 是因为最大色卡 291 色，远超 `Uint8Array` 上限没必要，但 256 也不够（291 > 255），所以取 16 位。

## 5. 颗粒度

主控件是**宽度格数**滑块，范围 10–200，默认 **29**。高度按原图宽高比自动计算，提供"锁定正方形"开关。

预设按钮：

| 预设 | 格数 | 场景 |
|---|---|---|
| 钥匙扣 | 20×20 | 小挂件 |
| 单板 | 29×29 | 一块标准方形底板，不用拼接 |
| 四板 | 58×58 | 拼 2×2 块板 |
| 大图 | 100×100 | 挂画级 |

滑块下方常驻一行实时回显：

> `29 × 34 格 · 986 颗 · 5mm 豆 ≈ 14.5 × 17.0 cm · 需 1×2 块底板`

这行的存在理由：颗粒度的真实含义不是"多少格"，而是"拼出来多大、要买几块板、要拼多久"。物理尺寸 = 格数 × 豆径；底板数按 29×29 钉一块换算（5mm 豆），2.6mm 豆按 57×57 钉一块换算。

豆子尺寸 5mm / 2.6mm 可切换，影响上述读数，并过滤可选色卡（Artkal C 是 2.6mm 专用）。

## 6. 色卡

### 6.1 数据源

来自 [maxcleme/beadcolors](https://github.com/maxcleme/beadcolors)，**MIT 协议**。构建期把 `gen/v3/*.csv` 编译成 TS 常量，运行时零解析开销。

CSV 字段：`code, name, symbol, R, G, B, H, S, L, L*, a*, b*, contributor`。**L\*a\*b\* 已预算**，感知色差匹配零转换成本。

内置五套：

| 品牌 | 色数 | 豆径 |
|---|---|---|
| MARD（漫漫/COCO 系） | 291 | 5mm |
| Artkal S | 199 | 5mm |
| Artkal C | 174 | 2.6mm |
| Perler | 103 | 5mm |
| Hama | 92 | 5mm |

数据源需在仓库内保留 `THIRD_PARTY_NOTICES.md`，附 MIT 许可全文与出处。

### 6.2 两个已确认的数据缺陷

**颜色名缺失**：MARD 体系没有颜色名，`name` 列等于 `code`（`F4` 就叫 `F4`）。Artkal / Perler / Hama 有真实颜色名（`Tangerine`、`Shamrock`）。

处理：为全部色卡补 `nameZh` 中文名。按 HSL 色相 + 明度 + 饱和度自动归类生成基础名（如"亮红""深蓝灰""浅米黄"），常用色（黑白灰、正红正蓝等）人工校对覆盖。生成脚本产出的映射表落盘为源码，不在运行时计算。

**符号列不可用**：数据源的 `symbol` 列是机器按 ASCII 码序自动分配的，红色 `F4` 分到 `è`，黑色 `H16` 分到 `Ζ`，人眼无法区分。

处理：符号模式改用我们自建的符号集。从一组高辨识度字形中按色相分配（`▲ ○ ◇ ■ ♥ ● □ ★ ▼ △ ✕ ＋ ...`），保证同一张图纸内出现的符号两两易辨。分配在生成 `BeadGrid` 后按**实际用到的颜色**动态进行，而不是全色卡静态分配——因为一张图纸通常只有 10–30 色，只需保证这些之间可辨。

### 6.3 「我有的豆子」子集

全色卡网格勾选面板，支持全选 / 反选 / 清空。勾选结果按 `paletteId` 存 localStorage。

匹配阶段只在勾选子集内找最近色。子集为空时视为全选。

这是实拼时最刚需的功能：买的是 48 色套装，图纸却给了 80 种颜色，等于白生成。

## 7. 编辑与持久化

三件套：

| 功能 | 交互 |
|---|---|
| 单格改色 | 点击 / 按住拖动连续涂 |
| 吸管 | `Alt` + 点击取色 |
| 撤销 / 重做 | `⌘Z` / `⌘⇧Z` |

手改存为 BeadGrid 之上的 **patch 层**（`Map<cellIndex, beadIndex>`）。因此改图纸样式、切色号显示、重跑渲染都不会冲掉手改。

**patch 失效规则**：改变颗粒度（宽/高格数）会让格子索引失去意义，此时必须丢弃 patch。触发时弹确认框，用户确认后才应用新颗粒度。改变色卡时，patch 中的 `beadIndex` 指向旧色卡，同样丢弃并确认。改变其它参数（亮度、抖动、色数上限等）不影响 patch —— patch 在管线跑完后覆盖上去。

**持久化**：不提供工程文件下载按钮。改为在 patch 变更时 debounce 写入 localStorage（连同当前参数与原图的 dataURL）。页面加载时若存在存档，提示"恢复上次编辑？"。这样刷新、崩溃、误关标签页都不丢工作，且不多一个导出按钮。

localStorage 容量约 5MB，原图 dataURL 可能超限。处理：存档前把原图按最长边 1200px 重编码为 JPEG（质量 0.85）再存；若仍超限则放弃存原图，只存参数与 patch，恢复时提示用户重新选择图片。

## 8. 算法

### 8.1 降采样：区域平均

降到 29×29 是极端压缩，最近邻会整个丢掉特征（一只眼睛、一根发丝可能凭空消失）。区域平均（box filter）保留每格覆盖区域的平均色。

代价是细线条会糊。因此提供采样方式开关：

- **平均**（默认）：区域算术平均，在 linear RGB 空间平均而非 sRGB —— 在 sRGB 空间直接平均会让结果偏暗。
- **中位数**：取区域内各通道中位数，抗噪点，适合手机拍的照片。
- **最近邻**：取区域中心像素，适合原本就是像素画的输入。

### 8.2 匹配：CIEDE2000 + 唯一色去重

匹配用 CIEDE2000 在 Lab 空间做最近邻。RGB 欧氏距离在肤色和渐变上表现明显更差。

**性能**：200×200 = 40000 格 × 291 色 = 1160 万次 CIEDE2000，直接算会卡。但降采样后的**独立颜色数远小于格数**。因此：先收集 unique colors（用 `Map<packedRgb, ...>`），每种只匹配一次，再映射回全网格。

先不上 Web Worker。若实测 200×200 仍有可感卡顿，再加 —— 不预支复杂度。

### 8.3 抖动：默认关闭

误差扩散在屏幕上看着平滑，但在拼豆上每一颗孤立噪点都是一次实打实的手工劳动，且拼出来比轻微色带更难看。

提供三档：

- **关闭**（默认）
- **Atkinson**：只扩散 3/4 误差，平面更干净，推荐给需要渐变的场景
- **Floyd–Steinberg**：扩散最充分，噪点也最多

**误差在 linear RGB 空间累加，不在 Lab 空间**。在感知空间累加误差会扭曲扩散权重，这是容易写错的地方。

### 8.4 色数上限：量化在匹配之前

用户设"最多 N 色"时：先在 Lab 空间对采样结果做 median-cut 得到 N 个代表色，每个代表色再匹配到调色板。

不采用"先全量匹配再合并相近色"——后者会因为匹配阶段已经把相近色打散到不同豆号，合并时无法恢复全局最优。

默认不限色数；提供 8 / 12 / 15 / 20 / 24 快捷值。15 色以内对新手最友好。

### 8.5 去孤点

3×3 窗口扫描，若中心格的颜色在该窗口内出现次数 ≤ 阈值，替换为窗口内众数色。三档强度：

- **关闭**
- **弱**（默认）：阈值 1，即只清完全孤立的单颗
- **强**：阈值 2，清掉孤立的对子

对空格（`mask=0`）不处理，且众数统计忽略空格。

### 8.6 抠图

PNG 透明通道 alpha < 128 的格子直接置为空格。

另提供"去纯色背景"：取四角像素的中位色作为背景色，容差滑块（0–100，默认关闭）内的格子置为空格。

## 9. 渲染与图纸样式

四种样式，**默认 A**，其余为开关：

| | 样式 | 说明 |
|---|---|---|
| A | 色块 + 色号 | 每格写品牌色号，文字取黑/白由背景亮度决定（Luma > 0.55 取黑）。默认导出样式。 |
| B | 色块 + 符号 | 用 §6.2 自建符号集。黑白打印不失真、相近色可辨、色弱友好。 |
| C | 纯色块 + 侧边图例 | 格子内无标注。高颗粒度（100×100+）下唯一可读的方案。 |
| D | 圆豆拟真预览 | 带孔圆珠渲染，模拟烫完的样子。非施工图，是"值不值得拼"的决策依据。 |

通用装饰：
- 网格线（可关）
- 四边行列坐标
- 每 10 格加粗一条辅助线
- 底板分界虚线（按 29×29 或 57×57 划分，可关）

## 10. 统计

右侧常驻面板：

| 列 | 内容 |
|---|---|
| 色块 | 颜色方块 |
| 色号 | 品牌色号 |
| 中文名 | §6.2 补的名字 |
| 颗数 | 该色用量 |
| 占比 | 百分比 |
| 累计 | 累计百分比，用来判断"前几色占了多少" |

可按颗数降序（默认）或色号升序排序。顶部汇总：总颗数、用色数、空格数。

CSV 采购清单一键下载，字段：`色号,颜色名,中文名,HEX,颗数,占比`。CSV 需带 UTF-8 BOM，否则 Excel 打开中文乱码。

## 11. 导出

| 产物 | 说明 |
|---|---|
| 图纸 PNG | 当前样式的高清位图，四边带行列坐标。拼到一半被打断时靠坐标找回位置。 |
| PDF 分页 | 按 A4 自动切页，每页带页码 + 一行/一列重叠 + 拼接指引（"本页接第 3 页右侧"），末页附总览图与用量表。60×60 以上时是刚需。 |
| 圆豆预览 PNG | 样式 D 的高清渲染。 |
| 统计 CSV | 见 §10。 |

导出用离屏 Canvas 独立绘制，不复用屏幕预览的 Canvas —— 屏幕预览有缩放和 DPR 处理，直接复用会导致导出分辨率不可控。

## 14. 测试策略

Vitest，只覆盖算法层。UI 不写单测。

| 模块 | 验证方式 |
|---|---|
| `color/space.ts` | sRGB→Lab→sRGB 往返误差 < 1e-6；对照数据源 CSV 自带的 L\*a\*b\* 值校验（每个色卡抽样 20 色，误差 < 0.5） |
| `color/distance.ts` | **CIEDE2000 必须用 Sharma, Wu & Dalal (2005) 的 34 组官方测试数据验证** |
| `color/quantize.ts` | 给定 N 个聚簇明显的输入，median-cut 出的代表色数量正确、且落在各簇内 |
| `pipeline/sample.ts` | 纯色图降采样后仍是纯色；棋盘格降采样后是灰（验证 linear 空间平均） |
| `pipeline/despeckle.ts` | 构造单颗孤点被清除、成片色块不被误伤 |
| `model/stats.ts` | 计数总和 = 非空格数；占比总和 = 100% |
| `model/patch.ts` | undo/redo 栈边界、patch 覆盖顺序 |

CIEDE2000 这一条单独强调：该公式有多处色相角环绕和分段判断，凭直觉实现几乎必错，而错了之后的表现是"匹配结果略微有点怪"，很难靠肉眼发现。官方测试集是唯一可靠的验证手段。

## 15. 已知风险

| 风险 | 缓解 |
|---|---|
| 屏幕 HEX 与实物豆子有色差（塑料材质、批次、显示器校准） | UI 上标注提示；提供圆豆预览帮助判断；不承诺色彩绝对准确 |
| 200×200 大图性能 | 唯一色去重（§8.2）。若不够再上 Worker |
| localStorage 5MB 上限 | 原图降质存储，超限则只存参数（§7） |
| 中文名为自动生成，可能不自然 | 常用色人工校对；名字仅作辅助，色号才是权威标识 |
