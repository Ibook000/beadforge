# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Picabead (拼豆图纸生成器): a browser-only app that turns an uploaded image into a perler-bead pattern grid + bead usage stats. No server, no upload — all processing in the browser. TypeScript + Vite, strict mode, no frontend framework.

## 激活码/去水印系统（2026-08 新增）

- `src/auth/activation.ts` — 前端激活单例：初始化 Supabase 客户端（publishable key），调 RPC `redeem_key(code, deviceId)` 兑换，localStorage 缓存激活状态。核心函数 `shouldDrawWatermark()`（导出前调用）。

- 环境变量：`.env`（已 gitignore）需 `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY`（publishable key，设计为公开）。secret key 只用于本地/管理员生成卡密，绝不放前端。
- 离线语义：有激活缓存直接放行导出；无缓存时后台验证一次，失败不阻塞导出（下次联网回落为未激活）。

## Architecture

### The pipeline (`src/pipeline/build.ts`)
The core is `buildGrid(src, params)`. Stage order is load-bearing — do not reorder:

```
sample → adjust → matte(mask) → quantize(optional) → match(±dither) → despeckle
```

Why this order (explained in `build.ts` comments):
- **Quantize before match**: median-cut in Lab space produces N representative colors *before* matching to the bead palette; matching-then-merging is a worse result by a tier.
- **Despeckle last**: removes isolated single-bead specks via 3×3 majority. If it ran before dithering, dithering would re-introduce the noise.

`applyQuantize` reuses the same CIEDE2000 matcher by wrapping median-cut representatives as pseudo-`Bead` objects — quantization and final matching share one color-difference code path.

### Patch layer (the key invariant)
`src/model/patch.ts` `PatchHistory` holds manual edits as `Map<cellIndex, beadIndex>`. **The grid is never mutated directly for edits.** `main.ts` `rebuild()` re-runs the whole pipeline, then overlays `history.current` on top. This is why adjusting brightness / changing sheet style preserves hand-edits — they live above the pipeline.

- Snapshot-based undo: each `apply`/`batchApply` stores a full Map copy. A pattern has typically dozens of edits, so each snapshot is a few KB — simpler than forward/inverse op pairs, no state drift.
- `ERASE = -1` (`src/ui/editor.ts`) is the sentinel for eraser semantics in the patch layer — `rebuild()` turns mask=1 cells into mask=0 when patch value is ERASE.
- **Changing granularity or palette invalidates cell indices / bead indices** → `history.clear()` (after a confirm for granularity). This is wired in `main.ts`.

### State (`src/ui/state.ts`)
Minimal hand-rolled store: `createStore()` with `get/set/subscribe`. `AppState` holds the pipeline output `grid`, the read-only `patch` snapshot (for UI), `highlightBead` (pulse-highlight index), `fullscreen`, `eraser`. The real edit history lives in `PatchHistory`, not the store — the store's `patch` field is just a UI-readable mirror.

`main.ts` is the single wiring point: store + history → mountControls / palettePanel / statsPanel / editor / preview, plus fullscreen mode, highlight pulse animation (requestAnimationFrame loop), localStorage archive save/restore, and SW registration.

### Color (`src/color/`)
- `space.ts` — sRGB↔Lab conversion.
- `distance.ts` / `ciede2000-testdata.ts` — CIEDE2000 (Sharma/Wu/Dalal 2005) with the 34 official test pairs as the correctness gate.
- `matcher.ts` — nearest-bead matcher, respects the "beads I own" subset.
- `quantize.ts` — median-cut in Lab.
- `dither.ts` — Atkinson / Floyd-Steinberg, error accumulates in linear RGB.

### Palettes (`src/palette/`)
Five palettes (MARD 291, Artkal S/C, Perler, Hama) as committed data files in `src/palette/data/*.ts`. `beads` use `Uint16Array` indices in `BeadGrid.cells` because MARD's 291 exceeds `Uint8Array`. Symbols are **not** stored on beads — `symbols.ts` assigns them dynamically per-sheet from the beads actually used (the upstream `symbol` column is machine-generated by ASCII code, unusable). "Only keep common colors" samples evenly across the palette + forces black/white in via Rec.709 luma sorting (see `palettePanel.ts`).

### Export (`src/export/`)
- `png.ts` `renderSheetToCanvas` draws: white bg → info header (top-left, website/contact + grid/palette/bead-count/color-count) → `drawSheet` (offset down by header height) → legend → watermark (last, on top). Uses an offscreen canvas (not the preview canvas) so export resolution is independent of display DPR.
- `legend.ts` — color swatches (rounded) + code + count.
- `watermark.ts` — single centered rotated `IBO0OK`. `ENABLE_WATERMARK` macro turns all export watermarks on/off. `ensureFontsReady()` awaits `document.fonts.ready` before export so canvas text uses the loaded Google Fonts (ZCOOL KuaiLe / Noto Sans SC) rather than fallbacks.
- `pdf.ts` — jsPDF is **lazy-loaded** via `await import('jspdf')` (~830KB, first-load only when user exports PDF). Vector grid cells; Chinese headers/legend names rendered as tiny PNG strips (jsPDF built-in fonts are WinAnsi). A4 paged with overlap + overview/usage page.

### Render (`src/render/`)
`sheet.ts` `drawSheet` supports styles `code` / `symbol` / `plain` / `round`, plus the puzzle-assembly `SheetHighlight` (same-color breathing tint via pulse phase, other colors dimmed). `decorations.ts` draws grid lines / coords / 10-cell major lines / board lines. `preview.ts` wraps the on-screen canvas with DPR scaling and adaptive cell size.

## Build / deploy notes

- `vite.config.ts`: `base: './'` (relative paths, works on any static host subpath), `assetsInlineLimit: 0` + `inlineDynamicImports: false` — keeps JS as separate chunks. **Do not inline everything into one big file**: a 900KB inlined `<head>` script gets Content-Type-misdetected as text/plain on some static hosts (Vercel/GitHub Pages render raw code). This was a real past failure.
- `.github/workflows/deploy.yml`: push to `main` → `npm ci → npm test → npm run build → deploy to GitHub Pages`. Vercel is git-connected for auto-deploy too.
- `public/sw.js` (Service Worker v2): **network-first for HTML, cache-first for static assets**. SW v1 cached HTML cache-first and served stale HTML that referenced new chunk filenames → 404. Don't go back to cache-first for HTML.

## Conventions

- Strict TypeScript. `BeadGrid.cells` is `Uint16Array` (max palette 291 > 255). All consumers must check `mask[i] === 1` before reading `cells[i]` — empty cells have meaningless `cells` values.
- Code comments are in Chinese and explain *why* (design tradeoffs), not what. Match this density and language in the files you touch.
- Tests live next to source as `*.test.ts`; `vite.config.ts` includes `src/**/*.test.ts`, environment `node`.
